## Cross-Resource Authentication via Managed Identity & OIDC Federation
This guide outlines how to authenticate a workload inside an Azure Kubernetes Service (AKS) cluster to access external Azure resources (such as Azure Key Vault) securely using User-Assigned Managed Identities and OIDC Workload Identity Federation, eliminating the need for hardcoded client secrets or tokens.

Architecture Overview
```text
┌─────────────────────────────────────────────────────────────┐
│                        AKS Cluster                          │
│                                                             │
│  ┌───────────────────────────┐     ┌─────────────────────┐  │
│  │   Kubernetes Service      │ ─── │    Pod / Container  │  │
│  │   Account (SA)            │     │   Workload / CSI    │  │
│  └─────────────┬─────────────┘     └──────────┬──────────┘  │
└────────────────┼──────────────────────────────┼─────────────┘
                 │ (OIDC Issuer Trust)          │
                 ▼                              │
┌─────────────────────────────────────┐         │
│  Azure AD / Entra ID                │         │
│  ┌───────────────────────────────┐  │         │ (Uses Azure SDK /
│  │ User-Assigned Managed Identity│  │ ◄───────┘  Secret Store CSI)
│  └─────────────┬─────────────────┘  │
└────────────────┼────────────────────┘
                 │ (RBAC Assignment)
                 ▼
┌─────────────────────────────────────┐
│          Azure Key Vault            │
└─────────────────────────────────────┘
```
#### Step-By-Step Implementation
### 1. Prerequisites & Environment Setup
Export environment variables used across setup commands:

```Bash
export SUBSCRIPTION_ID="<your-subscription-id>"
export RESOURCE_GROUP="keyvault-demo-rg"
export LOCATION="eastus"
export CLUSTER_NAME="keyvault-demo-cluster"
export KEYVAULT_NAME="aks-kv-demo-app"
export USER_ASSIGNED_CLIENT_ID_NAME="aks-kv-identity"
export SERVICE_ACCOUNT_NAME="workload-identity-sa"
export SERVICE_ACCOUNT_NAMESPACE="default"

az account set --subscription $SUBSCRIPTION_ID
```
### 2. Create Resource Group & OIDC/CSI-Enabled AKS Cluster
Create the resource group and deploy the AKS cluster enabling both OIDC Issuer (--enable-oidc-issuer) and the Azure Key Vault Secrets Provider Add-on (--enable-secret-store-csi-driver):

```Bash
# Create Resource Group
az group create --name $RESOURCE_GROUP --location $LOCATION

# Create AKS Cluster with OIDC and Secret Store CSI Driver enabled
az aks create \
  --resource-group $RESOURCE_GROUP \
  --name $CLUSTER_NAME \
  --node-count 1 \
  --enable-oidc-issuer \
  --enable-workload-identity \
  --enable-secret-store-csi-driver \
  --generate-ssh-keys

# Get Kubernetes credentials
az aks get-credentials --resource-group $RESOURCE_GROUP --name $CLUSTER_NAME
```
### 3. Deploy Azure Key Vault & Add Sample Secret
```Bash
# Create Azure Key Vault with RBAC Authorization
az keyvault create \
  --name $KEYVAULT_NAME \
  --resource-group $RESOURCE_GROUP \
  --location $LOCATION \
  --enable-rbac-authorization

# Add a test secret
az keyvault secret set \
  --vault-name $KEYVAULT_NAME \
  --name "db-password" \
  --value "SuperSecretValue123!"
```
### 4. Create User-Assigned Managed Identity & Assign RBAC Role
Create the Azure Managed Identity and grant it the Key Vault Secrets User or Key Vault Administrator role over the vault.

```Bash
# Create Managed Identity
az identity create \
  --name $USER_ASSIGNED_CLIENT_ID_NAME \
  --resource-group $RESOURCE_GROUP

# Retrieve Client ID and Principal ID
export USER_ASSIGNED_CLIENT_ID=$(az identity show --resource-group $RESOURCE_GROUP --name $USER_ASSIGNED_CLIENT_ID_NAME --query clientId -o tsv)
export IDENTITY_PRINCIPAL_ID=$(az identity show --resource-group $RESOURCE_GROUP --name $USER_ASSIGNED_CLIENT_ID_NAME --query principalId -o tsv)
export KEYVAULT_SCOPE=$(az keyvault show --name $KEYVAULT_NAME --query id -o tsv)

# Assign Key Vault Administrator / Secrets User role to Managed Identity
az role assignment create \
  --role "Key Vault Administrator" \
  --assignee $IDENTITY_PRINCIPAL_ID \
  --scope $KEYVAULT_SCOPE
```
### 5. Establish OIDC Federated Identity Credential Trust
Extract the AKS cluster's OIDC Issuer URL and establish federated identity trust between the Kubernetes Service Account and the Azure Managed Identity:

```Bash
# Get AKS OIDC Issuer URL
export AKS_OIDC_ISSUER=$(az aks show --resource-group $RESOURCE_GROUP --name $CLUSTER_NAME --query "oidcIssuerProfile.issuerUrl" -o tsv)

# Create Federated Identity Credential
az identity federated-credential create \
  --name "aks-federated-credential" \
  --identity-name $USER_ASSIGNED_CLIENT_ID_NAME \
  --resource-group $RESOURCE_GROUP \
  --issuer $AKS_OIDC_ISSUER \
  --subject "system:serviceaccount:${SERVICE_ACCOUNT_NAMESPACE}:${SERVICE_ACCOUNT_NAME}" \
  --audience "api://AzureADTokenExchange"
```
### 6. Create Kubernetes Service Account & SecretProviderClass
Annotate the Kubernetes Service Account with the Azure Managed Identity's Client ID:

```YAML
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: ServiceAccount
metadata:
  name: workload-identity-sa
  namespace: default
  annotations:
    azure.workload.identity/client-id: "${USER_ASSIGNED_CLIENT_ID}"
EOF
```
Define the SecretProviderClass specifying which Azure Key Vault and secrets to fetch:

```YAML
cat <<EOF | kubectl apply -f -
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: azure-kv-provider
  namespace: default
spec:
  provider: azure
  parameters:
    usePodIdentity: "false"
    useVMManagedIdentity: "false"
    clientID: "${USER_ASSIGNED_CLIENT_ID}"
    keyvaultName: "${KEYVAULT_NAME}"
    cloudName: ""
    objects: |
      array:
        - |
          objectName: db-password
          objectType: secret
          objectVersion: ""
    tenantId: "$(az account show --query tenantId -o tsv)"
EOF
```
### 7. Deploy Pod & Verify Access
Deploy a test workload mounting the Key Vault secret volume via the CSI driver:

```YAML
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: sample-workload-pod
  namespace: default
  labels:
    azure.workload.identity/use: "true"
spec:
  serviceAccountName: workload-identity-sa
  containers:
    - name: busybox
      image: registry.k8s.io/e2e-test-images/busybox:1.29-2
      command:
        - "sh"
        - "-c"
        - "while true; do sleep 3600; done"
      volumeMounts:
        - name: secrets-store-inline
          mountPath: "/mnt/secrets-store"
          readOnly: true
  volumes:
    - name: secrets-store-inline
      csi:
        driver: secrets-store.csi.k8s.io
        readOnly: true
        volumeAttributes:
          secretProviderClass: "azure-kv-provider"
EOF
```
