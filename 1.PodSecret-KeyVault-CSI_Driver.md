## Pod Accessing Secrets from Azure Key Vault via Secrets Store CSI Driver
In this video tutorial by Abhishek.Veeramalla, Option 1 represents the primary hands-on architecture where a Kubernetes Pod running inside an Azure Kubernetes Service (AKS) cluster securely mounts and consumes sensitive data stored in Azure Key Vault.

Overview of the Solution
Instead of hardcoding secrets in application code or storing them directly as native Kubernetes Secrets (which lack built-in lifecycle rotation policies), this pattern mounts Azure Key Vault secrets directly into the Pod's filesystem as volumes [

Key Components & Concepts  
 1. **Secrets Store CSI Driver & Azure Provider**   
   - The Secrets Store CSI Driver is a Kubernetes special-interest-group (SIG) plugin that enables Kubernetes to mount secrets, keys, and certificates stored in external secrets stores as a volume.
   - The Azure Key Vault Provider addon acts as the translator between the generic CSI driver interface and the Azure Key Vault API [


2. **Azure Workload Identity & Service Account**
   - Uses OIDC (OpenID Connect) issuer capabilities on AKS to bind a Kubernetes ServiceAccount to an Azure Managed Identity.
   - This provides passwordless, fine-grained authentication so that only specific authorized Pods can fetch secrets 

3. **SecretProviderClass Custom Resource**
   - A Kubernetes Custom Resource Definition (CRD) that tells the CSI driver which Key Vault instance to connect to and which secret keys to retrieve.

***Step-by-Step Implementation Flow***
##### Step 1. Provision the AKS Cluster with Required Addons  
Enable the Azure Key Vault Secrets Provider addon and the OIDC issuer when provisioning your AKS cluster:

```Bash
az group create --name rg1 --location eastus

az aks create --name AKS-KV-Cluster -g rg1 --node-count 1 --enable-addons azure-keyvault-secrets-provider --enable-oidc-issuer --enable-workload-identity
```
Get the K8S cluster credential
```
az aks get-credentials --resource-group rg1 --name AKS-KV-Cluster
```
Check current context 
```
>kubectl config current-context
# set current context
kubectl config use-context AKS-KV-Cluster
```
##### Step 2. Create Azure Key Vault & Secrets
Create an Azure Key Vault instance and populate it with your sensitive key-value pairs (e.g., secret1):

```Bash
az keyvault create --name aks-kv-demo-123 --resource-group rg1 --enable-rbac-authorization

# : Assign the RBAC Role to Your Account (Recommended)
# Find your user object ID or signed-in identity

$USER_OBJECT_ID="$(az ad signed-in-user show --query 'id' -o tsv)"

# Assign the "Key Vault Secrets Officer" role:
az role assignment create --role "Key Vault Secrets Officer" --assignee $USER_OBJECT_ID --scope "/subscriptions/<Subs_ID>/resourceGroups/rg1/providers/Microsoft.KeyVault/vaults/aks-kv-demo-123"


# Add a test secret
az keyvault secret set --vault-name "aks-kv-demo-123" --name "db-password" --value "SuperSecretPassword123!"
```
##### Step 3. Setup Managed Identity & RBAC Permissions
Create a User-Assigned Managed Identity and assign it the Key Vault Secrets Officer or Key Vault Administrator role on the Key Vault:

```Bash
## Create a user assigned MI
az identity create --name "keyvault-reader-identity" --resource-group rg1

# Export Client ID and Resource ID for reference
$USER_ASSIGNED_CLIENT_ID="$(az identity show -g rg1 -n keyvault-reader-identity --query 'clientId' -o tsv)"
$IDENTITY_RESOURCE_ID="$(az identity show -g rg1 -n keyvault-reader-identity --query 'id' -o tsv)"
```
##### Step 4: Assign Key Vault RBAC Role to Managed Identity
Grant the Managed Identity permissions (`Key Vault Administrator` or `Key Vault Secrets User`) over your Key Vault instance:
```
# Fetch Key Vault Resource ID and Managed Identity Client ID
$KEYVAULT_RESOURCE_ID="$(az keyvault show -n aks-kv-demo-123 --query 'id' -o tsv)"
$USER_ASSIGNED_CLIENT_ID="$(az identity show -g keyvault-demo-rg -n keyvault-reader-identity --query 'clientId' -o tsv)"

# Assign RBAC Role
az role assignment create --role "Key Vault Administrator" --assignee $USER_ASSIGNED_CLIENT_ID --scope $KEYVAULT_RESOURCE_ID
```
##### Step 5: Retrieve the OIDC Issuer URL
Fetch your AKS cluster's OIDC Issuer URL so Azure Active Directory (Entra ID) can verify tokens issued by your Kubernetes cluster:
```
$AKS_OIDC_ISSUER="$(az aks show -n AKS-KV-Cluster -g rg1 --query "oidcIssuerProfile.issuerUrl" -o tsv)"
echo $AKS_OIDC_ISSUER
```
##### Step 6: Create Kubernetes ServiceAccount & Establish Federated Credential
# Get managed ID client ID
az identity show --name "keyvault-reader-identity" --resource-group rg1 --query "clientId" -o tsv

1. Define Kubernetes ServiceAccount (service-account.yaml):
```
apiVersion: v1
kind: ServiceAccount
metadata:
  name: workload-identity-sa
  namespace: default
  annotations:
    azure.workload.identity/client-id: "<MANAGED_IDENTITY_CLIENT_ID>"
```
2. Link ServiceAccount to Azure Managed Identity:
```
az identity federated-credential create --name "aks-federated-identity" --identity-name "keyvault-reader-identity" --resource-group rg1 --issuer $AKS_OIDC_ISSUER --subject "system:serviceaccount:default:workload-identity-sa"
```
##### Step 7: Create the SecretProviderClass Manifest
Define the SecretProviderClass object (secret-provider-class.yaml) specifying which Key Vault and secrets to fetch:

```YAML
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: azure-kvname-user-msi
  namespace: default
spec:
  provider: azure
  parameters:
    usePodIdentity: "false"
    useVMManagedIdentity: "false"
    clientID: "<MANAGED_IDENTITY_CLIENT_ID>"
    keyvaultName: "aks-kv-demo-123"
    objects: |
      array:
        - |
          objectName: db-password
          objectType: secret
    tenantId: "<AZURE_TENANT_ID>"
```
##### Step 8: Deploy the Pod and Mount the CSI Volume
Create the application Pod manifest (pod.yaml) referencing the ServiceAccount and mounting the CSI volume:
```YAML
apiVersion: v1
kind: Pod
metadata:
  name: busybox-secrets-test
  namespace: default
  labels:
    azure.workload.identity/use: "true"
spec:
  serviceAccountName: workload-identity-sa
  containers:
    - name: busybox
      image: registry.k8s.io/e2e-test-images/busybox:1.29-2
      command: ["sleep", "3600"]
      volumeMounts:
        - name: secrets-store-inline
          mountPath: "/mnt/secrets-store"
          readOnly: true
  volumes:
    - name: secrets-store-inline
      csi:
        driver: secrets-store.csi.k8s.io
        readOnly: true
        volumeAttributes:
          secretProviderClass: "azure-kvname-user-msi"
```
Verification:
```
kubectl exec busybox-secrets-test -- cat /mnt/secrets-store/db-password
```
