### Dynamic Secrets Integration in CI/CD Pipelines via Azure Key Vault
This guide details how to integrate Azure Key Vault into CI/CD workflows (such as GitHub Actions and Azure DevOps) to dynamically fetch credentials, secrets, and connection strings at runtime—avoiding hardcoded secrets in source control or static environment variables.

#### Architectural Overview
Instead of storing database passwords, Docker registry tokens, or API keys directly inside pipeline settings or repository secrets, the pipeline authenticates to Azure via OpenID Connect (OIDC) / Managed Identity and retrieves values dynamically during workflow execution.
```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              CI/CD Runner                                   │
│                       (GitHub Actions / Azure Pipelines)                    │
│                                                                             │
│   1. Authenticate via OIDC (Short-Lived Token / Service Connection)         │
│   2. Fetch Secrets Dynamically from Key Vault                               │
│   3. Inject Secrets into Step Execution Context                             │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       │ HTTPS / Azure REST API
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                             Azure Key Vault                                 │
│                                                                             │
│   ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────────┐   │
│   │ Registry Tokens  │   │ Database Keys    │   │ Deployment Credentials │   │
│   └──────────────────┘   └──────────────────┘   └──────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
```
#### Key Concepts & Components Used
1. `Azure Key Vault`: Central repository holding execution credentials, registry login secrets, and infrastructure keys.

2. `OIDC / Service Principal Authentication`: Passwordless identity federation that permits CI/CD runners to request short-lived access tokens from Azure Entra ID.

3. `Azure Key Vault Actions / Tasks`: Pre-built workflow steps that fetch secret values at runtime and mask them in build logs automatically.

#### High-Level Implementation Steps
1. Create or Identify an Azure Key Vault Instance.

2. Store CI/CD Secrets in Key Vault.

3. Configure OIDC / Service Principal Credentials for the Pipeline.

4. Grant Key Vault RBAC Permissions to the Pipeline Identity.

5. Define the Pipeline Workflow File to Fetch & Inject Secrets.

Verify Execution & Secret Masking in CI/CD Logs.

Step-by-Step Implementation Flow
1. Create Azure Key Vault & Store Secrets
Ensure an Azure Key Vault instance exists and store your required pipeline credentials:

```Bash
# Create Key Vault with RBAC enabled
az keyvault create --name "cicd-demo-kv-123" --resource-group "rg1" --enable-rbac-authorization

# Store test secrets for CI/CD usage
az keyvault secret set --vault-name "cicd-demo-kv-123" --name "DOCKER-REGISTRY-PASSWORD" --value "SuperSecretDockerPass123!"

az keyvault secret set --vault-name "cicd-demo-kv-123" --name "DB-CONNECTION-STRING" --value "Server=tcp:demo.database.windows.net;Database=appdb;"
```
2. Set Up Azure Service Principal for OIDC (GitHub Actions)
Create an Azure Entra ID Application and Federated Credential so GitHub Actions can authenticate without storing long-lived client secrets:  
- [!Reff Doc](https://learn.microsoft.com/en-us/cli/azure/ad/app/federated-credential?view=azure-cli-latest&utm_source=gemini)  
- [!StepBy_Guide_azure](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation-create-trust?utm_source=gemini&pivots=identity-wif-apps-methods-azp)

```Bash
# 1. Create App Registration / Service Principal
$APP_ID=$(az ad app create --display-name "github-actions-keyvault" --query "appId" -o tsv)
$SP_ID=$(az ad sp create --id $APP_ID --query "id" -o tsv)

# 2. Add Federated Credential for GitHub Actions Repository
az ad app federated-credential create \
  --id $APP_ID --parameters '{
    "name": "github-main-branch",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:raghvendrashrinet/Azure-Key-Vault:ref:refs/heads/main",
    "description": "Federated credential for main branch execution",
    "audiences": ["api://AzureADTokenExchange"]
  }'
```
3. Assign Key Vault RBAC Role to Pipeline Identity
Grant the Service Principal access to read secrets from Key Vault:

```Bash
KEYVAULT_RESOURCE_ID=$(az keyvault show -n "cicd-demo-kv-123" --query "id" -o tsv)

az role assignment create \
  --role "Key Vault Secrets User" \
  --assignee $APP_ID \
  --scope $KEYVAULT_RESOURCE_ID
```
4. GitHub Actions Workflow Configuration
Create .github/workflows/deploy.yml in your repository:

```YAML
name: Key Vault Secrets Integration

on:
  push:
    branches: [ "main" ]

permissions:
  id-token: write   # Required for OIDC authentication
  contents: read

jobs:
  fetch-secrets-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Authenticate to Azure via OIDC
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}

      - name: Fetch Secrets from Azure Key Vault
        uses: Azure/get-keyvault-secrets@v1
        with:
          keyvault: 'cicd-demo-kv-123'
          secrets: 'DOCKER-REGISTRY-PASSWORD, DB-CONNECTION-STRING'
        id: kvSecretsStep

      - name: Run Build / Deployment Step
        run: |
          echo "Successfully retrieved secrets from Azure Key Vault."
          # Secrets are automatically masked in build output:
          echo "Connecting using string: ${{ steps.kvSecretsStep.outputs.DB-CONNECTION-STRING }}"
```
5. Azure DevOps Pipeline Alternative (Azure Pipelines)
If using Azure DevOps, configure azure-pipelines.yml:

```YAML
trigger:
  - main

pool:
  vmImage: 'ubuntu-latest'

steps:
- task: AzureKeyVault@2
  inputs:
    azureSubscription: 'MyAzureServiceConnection'
    KeyVaultName: 'cicd-demo-kv-123'
    SecretsFilter: 'DOCKER-REGISTRY-PASSWORD, DB-CONNECTION-STRING'
    RunAsPreJob: true

- script: |
    echo "Using dynamically retrieved secret in build step..."
    echo "Docker password length is ${#DOCKER_REGISTRY_PASSWORD}"
  displayName: 'Execute Deployment Script'
```
